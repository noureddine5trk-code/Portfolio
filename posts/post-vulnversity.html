Task 5 — Privilege Escalation

SUID (set owner user ID) lets a binary run with its owner’s privileges rather than the privileges of whoever launched it. That’s why /usr/bin/passwd — owned by root — can let any regular user edit a password-related file they’d otherwise have no access to: the binary itself briefly runs as root.

find / -perm -u=s -type f 2>/dev/null

One binary jumps out:

  • SUID file that stands out: [redacted]
systemctl enable /tmp/root.service
systemctl start root

Catch the connection, and you’re root.

  • Root flag: /root/root.txt → [redacted]

Takeaways

  • Open ports and banner versions set the whole attack path — port 3333 was the real target the moment the scan finished.
  • Blocklists that filter .php but forget .phtml are a classic upload-bypass gap.
  • Any SUID binary that isn’t passwd / sudo — systemctl here hands you root outright.
